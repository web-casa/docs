Web.Casa 的 AI 助手不是面板上附加的聊天机器人 — 它是深入每个子系统的管理副驾驶。以下是真实场景，展示如何用一句自然语言替代多步骤手动操作。

## 一句话创建反向代理

**不用 AI：** 打开站点创建表单，填写域名，选择类型，输入上游地址，配置请求头，保存，等待证书签发。

**用 AI：**

> "帮我创建 api.example.com 的反向代理，指向 localhost:3000，开启 HTTPS"

AI 调用 `create_host`，配置上游地址，Caddy 自动签发 TLS 证书。你审查确认对话框并批准 — 完成。

## 用自然语言部署 Docker 应用

**不用 AI：** 手写 `docker-compose.yml`，管理环境变量，创建卷和网络，启动 Stack。

**用 AI：**

> "部署一个带 MySQL 和 Redis 缓存的 WordPress 站点"

AI 生成完整的 Compose 文件，包含正确的镜像版本、环境变量、卷挂载和网络配置。经你批准后，部署 Stack 并返回访问地址。

## AI 诊断 502 错误

**不用 AI：** SSH 到服务器，检查 Caddy 日志，检查上游容器状态，查看端口绑定，回顾最近的部署，关联时间戳。

**用 AI：**

> "我的站点 blog.example.com 返回 502，帮我查一下"

AI 执行 `get_host` 检查代理配置，`docker_ps` 确认上游容器是否运行，`docker_logs` 扫描错误日志，`get_system_metrics` 检查资源使用情况。然后解释根本原因 — 例如容器因 OOM 被杀死 — 并给出修复建议。

## 在 IDE 中管理服务器

通过 Model Context Protocol 暴露 **44 个 MCP 工具**，你的 AI IDE 变成服务器管理界面：

**在 Cursor / Windsurf / Claude Code 中：**

> "显示所有运行中的容器和资源占用"

IDE 通过 MCP 调用 `docker_ps` 和 `get_system_metrics`，在编辑器中直接显示结果。不需要浏览器标签页，不需要 SSH — 只用你的编辑器。

**更多 MCP 工作流：**
- "部署 my-app 的最新提交" → 触发 `deploy_project`
- "上次部署失败的构建日志是什么？" → 调用 `get_build_log`
- "创建一个叫 analytics 的 PostgreSQL 数据库" → 调用数据库创建工具
- "立刻把所有数据备份到 S3" → 触发 `trigger_backup`

## AI 代码审查

**不用 AI：** 部署前手动审查代码，检查硬编码密钥、缺少错误处理、SQL 注入向量。

**用 AI：**

> "审查我最新提交的代码，检查安全问题"

AI 调用 `review_code` 分析你的改动，检查：
- 硬编码的凭据或 API 密钥
- SQL 注入和 XSS 漏洞
- 缺少输入验证
- 性能反模式

返回带有严重程度和修复建议的结构化报告 — 在代码上线之前。

## 根据项目上下文生成 Dockerfile

**不用 AI：** 分析项目结构，识别语言/框架，确定正确的基础镜像，编写多阶段构建，配置构建参数。

**用 AI：**

> "为这个 Next.js 项目生成 standalone 模式的 Dockerfile"

AI 调用 `generate_dockerfile`，检查项目的 `package.json`、框架配置和目录结构，然后生成优化的多阶段 Dockerfile，包含正确的 Node.js 版本、构建步骤和生产配置。

## 自动化系统健康检查

**不用 AI：** 手动检查磁盘空间、审查容器状态、验证 SSL 证书、扫描多个服务的日志查找错误。

**用 AI：**

> "运行系统健康巡检"

AI 调用 `run_inspection`，检查磁盘使用率、内存压力、容器健康度、SSL 证书过期和配置有效性。返回 AI 生成的摘要和优先级建议 — 一条命令搞定。

## 告警自愈

**不用 AI：** 凌晨 3 点被告警叫醒，SSH 登录，排查告警，手动处理。

**用 AI：** 当监控告警触发时（如"磁盘使用率 > 90%"），**自愈引擎**自动：
1. 分析告警上下文
2. 定位原因（Docker 镜像缓存膨胀、日志轮转失败等）
3. 建议修复（`docker_prune` 或调整日志保留策略）

你审查并批准 — 或根据配置的策略让它自动修复。

## 一条命令完成完整部署

**不用 AI：** 创建项目、配置 Git、检测框架、设置构建流水线、创建反向代理、启用 HTTPS — 至少 6 个步骤。

**用 AI：**

> "把 https://github.com/my-org/my-app 部署到 myapp.example.com"

AI 调用 `auto_deploy`：克隆仓库、检测框架、触发构建、创建反向代理站点、签发 HTTPS 证书 — 一条命令全搞定。
