Web.Casa includes a built-in **AI assistant** with **73 tools** that can manage your server, diagnose issues, generate configurations, review code, run system health inspections, and auto-heal problems. It natively supports three API protocols, covering six major LLM providers.

> **Warning:** The AI assistant can execute real actions on your server (deploying projects, running commands, managing containers). A **confirmation dialog** is shown before risky operations, but you should still review each action carefully.

## Provider Presets

Web.Casa natively supports **6 providers** with **3 API protocols**:

| Provider | API Format | Base URL | Models |
|----------|-----------|----------|--------|
| **OpenAI** | `openai-chat` | `https://api.openai.com` | gpt-4o, gpt-4o-mini, o3-mini |
| **Anthropic** | `anthropic-messages` | `https://api.anthropic.com` | claude-sonnet-4-20250514, claude-haiku-4-20250414 |
| **Google Gemini** | `google-generativeai` | `https://generativelanguage.googleapis.com` | gemini-2.0-flash, gemini-2.5-pro |
| **DeepSeek** | `openai-chat` | `https://api.deepseek.com` | deepseek-chat, deepseek-reasoner |
| **Moonshot (Kimi)** | `openai-chat` | `https://api.moonshot.cn` | moonshot-v1-8k, moonshot-v1-32k, moonshot-v1-128k |
| **Zhipu (智谱)** | `openai-chat` | `https://open.bigmodel.cn/api/paas` | glm-4-flash, glm-4 |

Any **OpenAI-compatible** endpoint (Ollama, LM Studio, vLLM) also works by selecting the `openai-chat` format and entering a custom base URL.

## Configuration

1. Navigate to **Settings > AI**
2. Select a **provider preset** or choose custom
3. The **API format** is auto-selected based on the provider
4. Enter the **Base URL** for the API endpoint
5. Enter your **API Key** (encrypted with AES-GCM at rest)
6. Select the **Model** to use
7. Save settings and test the connection

> **Tip:** API keys are encrypted at rest and never exposed in the UI after saving.

### Embedding Model (Optional)

For **semantic search** and vector-based memory retrieval, you can configure a separate embedding model:

| Provider | Models |
|----------|--------|
| **OpenAI** | text-embedding-3-small, text-embedding-3-large, text-embedding-ada-002 |
| **Zhipu** | embedding-3, embedding-2 |

You can optionally provide separate credentials for the embedding endpoint (Base URL + API Key). If not specified, the main provider's credentials are used as fallback.

## Chat Interface

The AI assistant is accessible through a **chat panel** in the Web.Casa UI:

- **Conversation history** — previous messages are maintained within the session
- **Fullscreen mode** — expand the chat to full screen for complex interactions
- **Ctrl+Enter** to send messages
- Clear conversation history at any time

## Tools (73 Total)

The AI assistant has access to **73 tools** organized in 17 categories:

### Host Management (7 tools)
- `list_hosts` — list all reverse proxy hosts
- `get_host` — get details of a specific host
- `create_host` — create a new reverse proxy host
- `update_host` — modify an existing host
- `delete_host` — remove a host permanently
- `toggle_host` — enable or disable a host
- `clone_host` — duplicate a host configuration to a new domain

### Project Deployment (10 tools)
- `list_projects` — list all deployed projects
- `get_project` — get project details
- `create_project` — create a new project from a Git repository
- `deploy_project` — trigger a build and deployment
- `get_build_log` — retrieve build logs
- `get_runtime_log` — retrieve runtime logs
- `start_project` / `stop_project` — start or stop a project
- `rollback_project` — rollback to a specific build number
- `auto_deploy` — one-command: Git URL → project creation → framework detection → build → reverse proxy with HTTPS

### Docker Operations (10 tools)

### Database Operations (5 tools)

### File Management (5 tools)

## Key Capabilities

### System Health Inspection
The AI can run a comprehensive system audit checking disk usage, memory pressure, container health, SSL certificate expiration, and configuration issues. Results include an AI-generated summary with prioritized recommendations.

### Self-Healing Engine
When monitoring alerts fire, the AI's **SelfHealEngine** automatically analyzes the situation and suggests remediation actions. This is rate-limited (5-minute cooldown) and integrates with the monitoring alert system via EventBus.

### Auto-Diagnosis on Build Failure
When a project build fails (`deploy.build.failed` event), the AI automatically analyzes the build logs and provides a diagnosis with suggested fixes — no manual intervention needed.

### Compose Generation
Describe the application you want to deploy in natural language, and the AI generates a complete `docker-compose.yml`:

> "Set up a WordPress site with MySQL and Redis caching"

### Confirmation Dialog
Operations that modify your server trigger a **confirmation dialog** showing exactly what will be executed. You must approve before the action proceeds.
